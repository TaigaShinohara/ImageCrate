# 画像処理の安全対策と上限

この文書は、現行実装が受け入れるデータ、利用者の操作、処理を終える条件をまとめたものです。制限に達しても、未保存の選択と取得済み候補を残し、理由と次にできる操作を表示します。個別の試験結果・使用したブラウザ・未実施項目は[QA.md](QA.md)を参照してください。

実行時の外部ライブラリ・解析送信・変換サービスは追加していません。Chrome 116以上、Manifest V3、`extension/`をそのまま読み込む構成を保ちます。新しい全サイト常時アクセス・Cookie読取・debugger・webRequest権限は要求しません。

## 利用者に見える変更

1. **取得は処理量でも区切ります。** 重複URLや不正な画像候補が大量にあっても、1回で全部を解析し続けません。「続きの候補」で同じスキャンを再開します。新しい候補がない区切りでは、前の候補と選択を保ちます。スキャン全体の上限に達した場合は、その時点の取得分で終了します。
2. **プレビューは初期状態から自動表示します。** 既存のChrome配信元許可、または元ページの一時アクセスが使える収集済み画像を、可視範囲に近づいたときに取得します。アクセスできない配信元ではplaceholderと追加許可ボタンを表示し、許可拒否後に取得を行いません。遠隔URLを直接Imageへ設定することもありません。
3. **作業ページでの保存は、保存全体の予算を使います。** 取得量、出力量、経過時間、同じ画像の試行回数を保存開始時から数えます。中断分の再試行や作業ページの再読み込みで予算は戻りません。結果不明の書き込みを、確認なしで再試行することはできません。

プレビューを許可しなくても、画像の選択・検索・選択解除と「元の形式＋Chromeのダウンロード先」での明示保存は利用できます。未対応画像を元形式へ勝手に切り替えて保存することはありません。元データが必要なら、利用者が元形式を選んで保存します。

## 配信元の許可と通信

2026-11-02の本人指定で作業ページごとの再同意を廃止しました。Chromeに既存の配信元許可があれば、新しい作業ページでも自動取得します。埋め込みdata画像も自動で端末内処理します。追加許可が必要な場合は、取得先のscheme・hostname・portと範囲を表示してから実click内で要求します。Chromeのhost許可は、同じscheme・ホストの**全パス・ポート**に及びます。URLごと・ポートごとだけの許可ではありません。

activeTab由来の一時アクセスは`permissions.contains()`と別に確認します。Chrome116では[通常の許可照会](https://raw.githubusercontent.com/chromium/chromium/116.0.5845.96/chrome/browser/extensions/api/permissions/permissions_api.cc)と[tab固有の一時許可](https://raw.githubusercontent.com/chromium/chromium/116.0.5845.96/chrome/browser/extensions/active_tab_permission_granter.cc)が分かれています。workerは現在のworkspace instance、正確な収集済み候補、有効なscan、HTTP(S)・認証情報を含まないURL、元ページとの同一origin、生存する元ページのURL一致・非loadingを検証します。fetch/cache/生成後にも同じ利用可否を再確認し、実際の取得権限はChromeが適用します。元ページの移動・閉鎖で旧プレビューを失効させます。Chromeの配信元許可取消では即時に生成画像/cache/処理中jobを失効させ、取消対象の配信元を一時アクセスへ切り替えて再取得しません。再許可はblocked previewの自動復帰に使います。

プレビュー、変換、選択フォルダへの取得は次の方針を共通で使います。

| 項目 | 動作 |
| --- | --- |
| ブラウザのログイン状態 | `credentials:include`。対象サイトの既存セッションが使われる場合がある |
| Referer | `referrerPolicy:no-referrer`。送信しない |
| HTTPリダイレクト | `redirect:error`。同じホストへの転送も含め、追跡せず中断する |
| 配信元の変更 | 他のホストへ許可を自動拡大しない |
| 埋め込みdata画像 | 対応する画像MIME・131072文字以下のdata URLだけを、明示同意後に端末内で処理。Chromeのhost許可は要求しない |

これはCookieの値や認証情報を独自に読み取る処理ではありません。Chromeの許可取消時は、待機中・取得中・表示中の該当プレビュー、同意、生成URLとcacheを失効させます。古い応答が後から来ても採用しません。

候補URLには認証queryが含まれる可能性があります。拡張が管理する作業情報はsession内で扱い、エラー表示ではURLを伏せます。元URLをChrome自身へ渡すdownloadでは、Chromeの履歴・キャッシュ等は別の保持範囲です。URLをGit・ログ・不具合報告へ貼らず、報告は合成データで再現してください。

## 作業情報と次回用保存先

Chromeが返す実保存先は受付・所有照合中の生のDownloadItemとして使い、sessionへはbasenameだけを保持します。旧sessionのjobs/historyも同じ規則へ移行します。要求した相対パスは照合のため別に保持し、移行でrevisionを巻き戻したり、予算・選択・試行回数を初期化したりしません。

作業ページの閉鎖後は不要な元ページURL・title、候補・選択・UI・履歴を取り除きます。結果未確定のjobのURL・binding・download ID・予算・lease・directory参照は保持し、実際の終端と後片付けの完了後にsessionを消します。時間だけで不明な保存を忘れて再送しません。

次回用の保存先記憶は、作業の復旧用handleと分かれています。既存保存設定の「次の作業でもこの保存先を使う」でOFFを適用すると、次回用メモを取り除き、OFFポリシーを保持します。現在の作業・batchの参照、保存済みファイル、Chromeの権限は保持します。取り消し・複数タブの競合・次回用記憶だけの失敗は、それぞれ明示して扱います。

保持範囲と元画像のメタデータ、報告窓口は [PRIVACY.md](PRIVACY.md) を参照してください。

## 上限

MiBは1024×1024 bytesです。文字数はUTF-16 code unitsで数え、byte数とは別です。画素数の「万」は10進です。

### 元ページの取得

| 対象 | 上限・区切り | 達した場合 |
| --- | --- | --- |
| 1回の取得候補・要素 | 500候補・12000要素 | cursorを返し、続きの操作で再開 |
| 解析入力の1属性 | 1048576文字 | 属性を除外し、後の要素へ進む |
| raw URL / 基準URL | 各131072文字 | URLの構築前に拒否 |
| srcset descriptor | 64文字 | その候補を除外 |
| 1回の解析仕事量 | 131072文字・4096 raw候補試行・25ms目標 | トークン途中の位置を保ち、続きへ |
| スキャン全体 | 16777216文字・65536 raw候補試行・100000要素 | 取得済み分を残して終了 |
| DOM変更の検査 | 512 mutation records・2048 nodes | 検査し切れない変更は保守的に継続無効化 |
| 参照するDOMルート・文書 | 256ルート・32文書 | 超過したshadow DOM・frameを除外 |
| 続き・再送の有効期間 | 5分 | 明示的な再スキャンが必要 |
| 元ページへの注入 | 同じsourceタブ1件、全体4件。応答待ちは5秒 | UIへ期限超過を返し、未settleの枠を再利用しない |

重複・不正・除外された候補も仕事量を消費します。CSS背景のURLも前方走査で処理します。DOM変更や元ページの移動・再読み込みでは、古いcursorや応答を新しいスキャンへ混ぜません。再送用には直前の1ページだけを保持します。内容を持たない処理区切りと、候補の保持容量不足は区別します。

既存の保持量の上限も維持します。候補ページのserialized予算は最大1.5MiB、重複確認は4096件・2MiB、取得するdata URLの合計は524288文字、同じURLの由来情報は64件までです。選択は作業タブごとに500件、作業タブは4つまでです。候補情報6MiB・session情報8MiBの共有予算があります。

25msはJavaScriptが処理を区切る目標です。DOM・style・URLなどブラウザnative呼出しの所要時間を25ms以内にする保証ではありません。5秒の応答待ち終了も、注入済みのnative処理をその瞬間に停止させる保証ではありません。worker再起動後も未解決の注入予約を保守的に保持し、元タブの終了などで終了を確認できるまで同じsourceへ重ねません。

### 作業ページで行う保存

この表は、選択フォルダへの元形式保存と、両保存先での形式変換に使います。元URLをChrome自身が取得する通常保存は、[別の境界](#chrome自身が取得する保存)です。

| 対象 | 上限 | 数え方 |
| --- | --- | --- |
| 選択フォルダへ元形式で保存する1試行 | 入力128MiB・120秒 | streamで受け取る展開済みbodyを確認 |
| 変換する1試行 | 入力32MiB・出力64MiB・120秒 | 取得・検査・codec・書き込みまでの同じ期限 |
| 変換元の寸法 | 2400万画素・片辺16384px | native codecより前の構造検査とdecode後の寸法照合 |
| 無進捗 | 30秒 | 取得・書き込み等が進まない場合に中断 |
| 同じ保存全体の入力 | 512MiB | 初回と中断後の試行を累積 |
| 同じ保存全体の出力 | 512MiB | 入力と分けて累積。元形式書き込みも含む |
| 同じ保存全体の時間 | 開始から15分 | 再試行・再読み込みで延長しない |
| 同じ画像の試行回数 | 初回を含め3回 | 論理的に同じ画像のattemptを数える |

開始前に入力・出力の予算を予約し、受信byteを確認してからchunkを保持・書き込みへ渡します。HTTPのContent-Lengthだけを信用しません。長さ不明・過小な長さ・圧縮された応答でも、実際に渡されたbodyを数えます。上限を超えたchunkはBlobの蓄積やファイルへの書き込みに受け入れません。

通信が失敗した試行の観測byteも累積します。古い作業ページの終了などで利用量が分からなくなった試行は、予約分を使ったものとして数えます。未知の利用量をゼロとして払い戻しません。成功した変換のローカル出力を、元URLからもう一度受信したbyteとして二重計上しません。

### プレビューと共有する画像処理資源

encodedはファイル形式の画像データです。表示画像相当のbyte数は、生成した幅×高さ×4の管理上の換算値で、ブラウザ内部の実メモリ量ではありません。

| 対象 | 上限 |
| --- | --- |
| プレビュー1件の入力・時間 | 8MiB・20秒。待機から同じ期限を使う |
| プレビュー元の寸法 | 2400万画素・片辺8192px |
| プレビュー生成寸法 | 最大辺384pxのサムネイル、2048pxの拡大用静止画。元画像より拡大しない |
| 開いている作業ページのプレビュー累積取得量 | 256MiB。表示変更・同じ画面での再試行で戻さない |
| 作業ページの待機・実行数 / cache件数 | 各64件まで |
| 作業ページのプレビューcache | encoded 16MiB、表示画像相当32MiB |
| 拡張全体のプレビューcache | encoded 32MiB、表示画像相当64MiB |
| 拡張全体の処理中encoded予約 | 128MiB |
| 拡張全体の処理中画素予約 | 6400万画素。検査した元画像・内包画像と出力canvasを含む |
| プレビューと変換のcodec | 拡張のorigin全体で1件 |
| プレビュー・作業ページ保存が共有する取得枠 | 作業ページごとに2件、全体4件。元URLをChrome自身が取得する保存はこの枠の外 |

作業ページごとの上限には、同じ作業の以前のページinstanceに属する未解決予約も含めます。用途・ページごとの後片付け所有者は分離し、プレビュー終了で変換の予約を消しません。cacheには保持する元Blobと生成出力の両方を数えます。codecの予約には元Blob・検査用ArrayBuffer・出力の許容量を含めます。表示中画像の生成URL、使われなくなったcache、Worker、bitmap、canvasは寿命に合わせて解放します。元Blobを画面のImageへ直接表示しません。表示するのは検査後に生成した静止画だけです。

画面の元画像寸法は、検査した元画像の寸法（必要なEXIF回転を反映）です。フィルターもこの寸法を使い、サムネイルのnaturalWidthを元画像の幅にしません。「プレビューを等倍で表示」は、生成した最大辺2048px以内の画像を等倍表示する操作です。

表示範囲外・絞り込み・viewerを閉じる操作では、その表示の取得待ちとURL参照を取り消します。同じ画像を別の表示が待っている間は共有取得を維持し、最後の表示が不要になったときに取り消します。非表示・作業ページ終了・host許可取消では古い表示世代を失効させます。作業ページを新しく読み込むとcache・累計取得量は新しく始まり、Chromeの既存許可または生存する元ページの一時アクセスで自動表示します。保存開始時に記録するbatchの予算とは別です。

## 対応する画像

ファイル名の拡張子やMIMEだけでnative codecへ渡しません。全入力が容量内に収まった後、有限の仕事量で構造を検査します。未対応・不明・不整合はプレビューと変換を拒否し、直接の元Blob表示や原形式への暗黙fallbackを行いません。

| 形式 | プレビュー・変換で検査する内容 |
| --- | --- |
| PNG / APNG | canvasと各frameの寸法・範囲・個数・終端。iCCP / zTXt / iTXt等の圧縮metadataは拒否 |
| JPEG | 対応する8bit符号化の寸法・成分・sampling・marker・終端。EXIFの回転と参照範囲。埋め込みthumbnail・複数画像の未対応構造は拒否 |
| GIF | logical screenと全frameの寸法・範囲・個数・blockの終端 |
| WebP | RIFFとcanvasに加え、ANMF内のVP8 / VP8L frameヘッダーまで検査 |
| BMP | 対応header・寸法・palette・非圧縮/bitfields。埋め込み圧縮画像やprofileを拒否 |
| ICO | すべてのentryと内包PNG / DIBの寸法・範囲。選んだ1件だけの検査ではない |
| SVG | 64KiB以下。ルートと最大128個の単色矩形（透明度可）だけを専用処理で描く。一般SVGのsanitizer・rendererではない |
| AVIF・未知のcontainer | プレビューと変換は未対応。codecを呼ばない |

frame / ICO entryは64件、内包する画素の合計は6400万画素、構造をたどるpartsは8192件までです。EXIFも参照数・項目数を制限し、循環参照を拒否します。SVGの外部画像・script・style・文字・filter・再帰的参照・一般のpath等は対応しません。対応するSVGでもnative SVG codecには渡しません。

JPEG出力の透明部分は白で塗り、PNG・WebP出力は透明部分を保持します。アニメーションを保持したい場合は元形式で保存してください。対応表は元形式保存のファイル検証保証ではありません。元形式保存は内容を変えず、画像として正常にdecodeできることを保証しません。

## 中断・結果不明と再開

保存設定、対象、名前、保存先、形式は開始時に固定します。確定した中断分は同じ設定・同じ保存予算で再試行します。別の形式や保存先でやり直す場合は、利用者が「中断分を新しい保存として準備」を選びます。既存ファイルは上書きせず、別名で保存します。

OSへのwrite・close・abortは、拡張の待ち時間を過ぎても後から終わる場合があります。UIを待たせ続けず「結果不明」として後続を止め、その間は書き込みlockと必要な画像予約を保持します。結果不明のファイルを自動削除したり、同じ画像を自動再試行したりしません。結果が確定していても、既存・置換済み・非空のファイルは後片付けで削除しません。

Chrome受付済みの変換Blobは、実際のcomplete / interruptedが確認できるまでURLと出力予約を保持します。作業ページを閉じた後の照合・解放は背景処理へ引き継ぎます。履歴が見つからないことや30秒が過ぎたことだけで、成功・確定した中断とは判定しません。

処理が実際に終了したと確認できない場合、予約が残って新しい処理を拒否することがあります。期限だけで未settleの資源を再利用しません。ブラウザ再起動でsession内の一時状態と予約は消えますが、保存先にある完成ファイル・未完成ファイルは消えません。先に保存先とChrome履歴を確認してください。ブラウザ終了をまたぐ作業状態の復元は保証しません。

## Chrome自身が取得する保存

「元の形式＋Chromeのダウンロード先」では、元URLの通信・ファイル書き込みをChromeが管理します。拡張のstream readerが各chunkを検査してから書き込む方式と同じ制御はできません。拡張が開始したdownload ID、自拡張の識別、開始時刻、名前、Chromeの状態を照合し、他の拡張や利用者が開始したダウンロードを対象にしません。

Chromeから得られる受信byte・総量・状態は観測値です。開始前には同じ保存全体の予算を予約し、開始後は`downloads.search`の観測で次の基準を確認します。

| Chrome通常保存の観測基準 | 動作 |
| --- | --- |
| 1試行の観測入力・出力 | 各128MiBまでを目安にし、観測で超えた場合は取消要求 |
| 1試行の経過時間・無進捗 | 開始から120秒・30秒無進捗を観測した場合は取消要求 |
| 同じ保存全体 | 観測入力・出力を別々に各512MiB、開始から15分、同じ画像は初回を含め3試行。残予算なし・期限超過・未確定では次の開始を拒否 |
| 照合の機会 | 作業ページ表示中の確認、downloadイベント、worker起動時、全owned active native jobsを対象とする内部アラーム |

受信量の値が戻っても、既に数えた量を払い戻しません。開始時刻不明や時計逆行では保守的に停止を要求します。未確定の受付・利用量は予約分を使ったものとして保持し、後で観測した超過分も加算します。取消要求と完了が競合するときは、実際のcompleteを保持します。Chromeの部分ファイル・完成ファイルを自動削除しません。

内部アラームはChrome 116互換の1分間隔で、worker休止・OSスリープ・背景処理によって確認が遅れる場合があります。120秒・30秒の経過を、その時刻ちょうどに検出・停止する保証ではありません。

拡張から観測して取消を要求する処理でも、書き込み前の厳密byte上限、超過量の厳密な上限、即時停止、Chrome内部の再送を含むwire総転送量の上限にはなりません。通常保存を、作業ページの入力128MiB・総512MiBと同じ事前制御として扱わないでください。

## 検証と未確認の境界

| 検査層 | 対象 | 結果の読み方 |
| --- | --- | --- |
| 単体試験 | 不正・重複・巨大な候補、入力/出力予算、偽のContent-Length、遅延Promise、deadline、native I/O結果不明、metadata、lease競合、許可取消、遅延結果 | fake clockと小さい注入上限で境界を再現。実OS/native内部の停止を確認した結果ではない |
| 隔離ブラウザ | 合成の配信元、実HTTP、Worker、生成Blob URL、同意ボタン、選択・保存、表示変更・終了時の後片付け | 一時profileとテストコピーを使う。具体的な実行版・合格範囲はQAに記録 |
